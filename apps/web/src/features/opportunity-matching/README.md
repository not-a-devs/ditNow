# TASK-AI-OPP-01B — 규칙 기반 기회 준비 도우미

FR-OPP-002/004, FR-AI-002/003의 제한된 규칙 기반 흐름이다. LLM 생성·외부 모델·자격 판정·실제 기관 제출 기능이 아니다. 기존 시설 검색 화면과 별도 로그인/원장을 만들지 않는다.

## 통합 계약

- 기본 export `OpportunityAssistant` (`OpportunityAssistant.tsx`)
- props: `sessionGeneration: string | number`, `onSaved: () => void`
- 인증·현재 사용자 확인·루트 보호·메모리 토큰은 공통 App 소유자 책임이다. 세션 세대가 바뀌면 추천·개인 초안 전체를 unmount한다.
- `onSaved`는 성공 또는 부분 저장 후 사용자가 **내 준비 목록으로 이동**을 눌렀을 때 호출하는 이동 callback이다. 완료 증거를 뜻하지 않는다. 실제 완료는 아래 서버 재조회 성공 문구로 구분한다.

## 사용자 흐름과 쓰기 경계

1. 사용자가 질문에서 찾고 싶은 키워드를 직접 확인한다. 쉼표 구분 최대5개·각20 Unicode code point이며 자연어 자동 해석을 하지 않는다.
2. 기존 GET `/me/opportunity-matches`와 `/{id}/brief`로 공고·규칙 근거·주의 사항을 읽는다. 빈 주관은 `미확인`으로 표시한다.
3. **준비 초안 만들기**에서 절차 기반 항목을 편집·선택한다. 메모1000자, 각 항목1~200자다. 초안은 메모리에만 있고 취소는 쓰기0이다.
4. **준비 초안 검토**는 최신 brief와 본인 준비 목록 GET만 수행한다. 원문·현재 범위·기간·절차 등이 달라지면 입력을 보존하고 재검토를 요구한다. 평가 시각만 바뀐 것은 원본 변경으로 간주하지 않는다.
5. 별도 동의 후 **확인하고 내 준비에 저장**만 쓰기를 시작한다. 다시 brief와 준비 목록을 확인하고, 기존 행은 메모·상태·체크를 그대로 둔 채 선택한 체크만 추가한다. 새 행은 기존 자연 멱등 PUT을 이용한다.
6. 체크 POST는 항목별 동일 요청 키·본문을 재시도에 유지한다. 성공 응답을 받은 체크는 재생성하지 않는다. 이후 본인 목록에서 응답 ID·텍스트·순서를 모두 확인한 경우에만 완료로 표시한다.

여러 기존 API를 조합하므로 일괄 원자 저장은 아니다. 일부 성공·응답 불명확·충돌을 표시하고 이미 저장된 내용을 삭제하거나 임의로 새 요청 키로 복제하지 않는다. 이전 저장 시도 뒤 현재 행이 없으면 자동으로 다시 생성하지 않는다. 원문이 저장 도중 바뀌면 추가 쓰기를 중단한다.

Unmount·세대 교체 시 AbortSignal과 요청 세대 검사로 뒤늦은 응답의 후속 쓰기·조회·callback을 차단한다. 클라이언트 취소는 이미 서버가 처리한 쓰기의 rollback을 보장하지 않으며, 현재 사용자 권한 판정은 서버 책임이다.

## 검증과 제한

- 전용 UI 테스트는 API 함수 대역 기반이며 실제 MariaDB/HTTP/browser 증거가 아니다.
- 2026-10-30 로컬: `npm ci --ignore-scripts --offline` 성공·audit0, 전용 `npm test -- src/features/opportunity-matching` **46개 통과**, `npm run typecheck`·`git diff --check` 통과.
- 마지막 401/403 폐기 회귀2개 추가 전 체크포인트에서 전체 웹552개·`npm run build`·`npm run api:types:check`가 통과했다. 최종 PR HEAD의 전체 CI 결과는 PR 본문에서 별도 확인한다.
- 실제 기회 API·공통 인증·루트 화면·생성 타입·NAV 통합과 승인된 실서버 검증은 각 소유자가 별도 수행한다.
- 이 작업에서는 비밀값·DB·유료 모델·운영 서버·실제 계정에 접근하지 않는다. 기존 `mvp/` 코드 재사용도 없다.

## TASK-OPP-UX-01 — 포커스·긴 문구·터치 영역 보완

NFR-UX-003, TC-V1-OPP-002/004의 접근성 보완이다. 초안을 열면 편집 제목, 검토하면 확인 제목, 다시 편집하면 편집 제목, 취소하면 원래 초안 열기 버튼으로 포커스를 보낸다. 초기 렌더에서 포커스를 빼앗지 않으며 제목의 scroll margin으로 고정 상단바 여유를 둔다.

긴 공고·주관·근거·메모를 자르지 않고 `overflow-wrap:anywhere`, `min-width:0`, grid `minmax(0,1fr)`로 줄바꿈한다. 이 영역 버튼·체크 label·근거 펼치기는 최소24px 높이를 지정한다. 저장·취소 API, 검토/동의, 권한·DB·소스 계약은 변경하지 않는다.

추가 회귀3개는 수정 전 실패를 확인한 뒤 보완했다. 전용49개·타입 검사를 통과했으며, 긴 문자열의 DOM 보존·CSS 지정과 실제 포커스를 jsdom에서 검증한다. **390/1280 실제 브라우저의 가로 넘침·터치 크기 수치·키보드 시연은 이 작업에서 NOT_RUN**이며 root가 최종 통합 후 별도 확인한다. 단위 검사로 실측을 대신하지 않는다.
