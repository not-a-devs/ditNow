# 정보 구조(IA) · 화면 · UX 계약

## 1. 역할별 내비게이션 [설계 기본값]
**공통**: 로그인, 통합 알림, 검색, 프로필/설정, 오류/권한 안내.

**학생 주요 탭 (모바일 5개 이하 권장)**
1. **홈**: 오늘 강의/학과 공식 소식/지원 기회/커뮤니티 알림/AI 행동 카드
2. **강의실**: 수강 과목 카드→과목별 공지·자료·과제·라이브·질문
3. **우리 학과**: 학과 전체 채팅·학년 채팅·자유 채널·공식 공지
4. **커뮤니티**: 전체 익명/학과 게시판, 실명 팀 모집·스터디·동아리
5. **더보기/기회**: 장학금·근로·공모전·학사·도서관·캠퍼스 생활

**교수**: 담당 강의실 / 수업 자료·과제 / 라이브 시작 / 수업 질문 / 담당 수업 공지.
**조교·학교 담당자**: 공식 공지 작성 / 대상 설정 / 공고·지원 안내 / 공식 채널 / 전달 현황.
**관리자**: 조직·학과·학년·강의·수강 / 사용자·범위권한 / 신고 / 로그.

## 3. 화면별 제품 동작
### 홈
- 첫 진입: 인사/오늘 수업/확인해야 할 공식 공지/기회/내 프로젝트·신청/AI 요약 순.
- 각 카드에서 원본 화면으로 진입. AI 카드에는 `AI 요약` 명시.
- 콘텐츠 없을 때 가짜 공지를 실제로 존재하는 것처럼 채우지 말고 빈 상태/시연용 데이터 표시.

### 우리 학과
- 상단: 학과명/공식 공지 요약. 아래: 학과 전체, 학년별, 자유 채널.
- 공식 알림 카드는 다른 메시지와 대비된 아이콘/라벨/출처와 원문 접근 제공.
- 학생 일반 채널에는 공식 배지가 표시되지 않음.

### 커뮤니티
- 익명 게시판과 실명 모집은 별도의 영역/작성 폼/프로필로 분리.
- 게시 직전 신원 표시 방식 안내. 익명 글에서 실명 프로필 링크 금지.
- 모집글에는 정원/마감/역할/지원 버튼/상태가 명확.

### 기회 상세
- 원본/주최기관/지원 대상/서류/기간/다운로드/제출 방법을 분리해서 표시.
- `외부 기관 직접 제출` 고지와 개인 준비 체크리스트; 사용자가 저장한 완료 상태임을 분명히 표시.

### 강의실
- 과목별 상단: 교수·분반/현재 수업시간/라이브 표시. 탭: 공지·자료·과제·질문(라이브는 별도 액션).
- 학생 라이브는 보기/확대/자료 독립 열람, 교수는 시작/종료/질문 목록.
- 영상 로딩/끊김은 별도 명확한 상태로 표시. 수업 외 사용자는 접근 차단.

## 4. 반응형 UX 품질
- 390px: 단일 열, 충분한 탭 터치 영역(목표 44px), 실시간 영상 aspect ratio 유지, 입력 바는 키보드에 가리지 않음.
- 1280px: 사이드바·콘텐츠 2열 가능, 강의 영상/질문 보조 패널.
- 폰트·색상·간격·버튼·에러 문구 토큰 통일. 색만으로 상태 구분하지 않음.
- 화면마다 `loading / empty / success / validation-error / network-error / permission-denied / session-expired`를 구체적으로 설계.
- 저장 중 버튼 중복 제출 금지, 저장 후 목록 갱신, 삭제 확인/취소, 작업 이탈 시 미저장 내용 경고(필요 시).

## 5. 작성/검색 폼 표준
- 게시글: 제목과 내용 길이 제한, 서버 재검증.
- 공식 공지: 대상·카테고리·게시일·출처 지정. 대상을 정하지 않은 경우 등록 금지.
- 채널 개설: 일반/공식 선택 불가 — 학생 폼은 일반 채널만.
- 외부 기회: 다운로드 URL/파일/제출처 정보 없으면 '정보 없음/원본 확인' 명시.
- 실시간 공유: 사용자 동작으로만 시작, 브라우저 공유 선택을 설명하며 중지 상태 명확히 표시.
