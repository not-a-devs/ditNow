# 역할·권한·공지 배포·커뮤니티 정책

## 1. 권한 모델 [설계 기본값]
정적 전역 `role` 하나로 모든 것을 결정하지 않는다. `role_assignments(user_id, role, scope_type, scope_id, granted_by, ...)` 방식으로 **업무 역할 + 소속 범위**를 함께 검증한다.
- 기본 인증 사용자: student, professor, assistant, department_staff, class_representative, school_staff, admin.
- 한 사용자가 학생이면서 총대일 수도 있다. 총대는 소속 학과×학년 범위에 한정된 보조 권한.
- 전역 관리자/학교 담당자는 서버/관리자 시드로만 부여. 가입할 때 스스로 교직원·관리자 선택 금지.
- 실명 표시는 시연 프로필일 수 있으며 학교 공식 재학생 인증과 동의어가 아님.

## 3. 익명 / 실명 경계 [확정 방향]
1. 전교 자유 소통·학과 익명 게시판은 대외 표시 익명.
2. 공모전·대회·프로젝트·스터디/동아리 참가 등 책임 있는 활동은 실명 표시.
3. 글 작성 시 선택한 게시판의 신원 규칙을 게시 후 바꾸지 않는다(익명 글을 실명 전환 금지).
4. 익명 API는 공용 응답에서 `author_id`, 실명, 계정 고유값, 신분을 절대 반환하지 않는다. DB RLS만으로 열 숨김 불가 → projection/view/server API 필요.
5. 운영자는 적법한 신고 처리 목적의 제한된 도구로만 작성자를 확인할 수 있으며 감사 기록을 남긴다.

## 4. 학과 채널 규칙 [확정 방향 + 기본값]
- 학과 전체 기본 채팅: `department_id`별 1개.
- 학과×학년 기본 채팅: `department_id + academic_year`별 1개.
- 자유 채널: 학생 자유 생성, `official=false`; `department_open` 또는 `approval_required` 중 선택(기본 `department_open`).
- 학교·학과 공식 채널: 권한자 승인 후에만 `official=true`로 발행.
- 멤버십: 소속이 검증된 프로필/가입 정보로 자동 계산. 실제 학적 연동이 없으므로 해커톤은 관리자 승인한 시연 소속만 사용.
- 소속 변경: 이전 학과 채팅 신규 읽기·전송 즉시 제한. 이전 기록 보존/삭제의 운영 정책은 별도 승인 필요 → **기본값은 이전 학과 채팅 더 이상 접근 불가**.
- 메시지 삭제: 작성자 본인의 일반 메시지는 삭제 표시, 원본 감사 기록은 제한적으로 보존.

## 5. 공식 공지 자동 배포 라우팅 [설계 기본값]
1. 작성자가 대상 scope를 택한다: `all_school / department / department_year / course / individual`.
2. 서버가 게시 권한 및 대상 존재를 검증한다.
3. 원본 `notices` 게시와 outbox 이벤트를 동일 트랜잭션으로 기록한다.
4. 대상 채널을 결정한다: 학과→학과 전체, 학년→학년별, 수업→수업 채널, 학교 전체→통합 공지/개인 알림(기본 채팅으로 일괄 발송하지 않음), 개인→개인 알림.
5. `(notice_id, revision, destination_id, event_type)` 고유값으로 중복 생성 방지.
6. 공지 카드에는 공식 출처, 대상, 버전, 원문 참조가 있어야 하며 내용 전체 복사 금지.
7. 게시 수정 시 원본 revision 업데이트, 중요 변경만 안내 재발송; 삭제/보관 시 기존 카드도 종료/비공개 메시지를 제공.
8. 알림은 같은 학생에게 다중 경로로 같은 공지가 도착하면 한 건으로 접어서 표시.

## 6. 학생 총대/대표 [확정된 맥락, 정책 제안]
- 현재 조교가 총대 단톡에 보내고 총대가 다시 복사해 학년 단톡으로 전달하는 구조를 줄이는 것이 목적.
- 총대는 공식 공지를 대신 작성한 것으로 표시할 수 없음. 학년 공지를 '공유'하거나 학년 학생 의견 수집·정리, 자유 채널 운영 가능.
- 공식 배지 부여는 교수/조교/관리자 등 승인된 주체에만 허용.

## 7. 기회·장학금 공고
- 학교가 소개하는 외부 장학금의 기본 접수 유형은 `external_document_submission`.
- 학생은 지정 파일 다운로드와 제출기관/방법/기한을 안내받고 기관으로 **직접 제출**한다.
- 앱에는 개인 상태를 '준비 중 / 제출했다고 기록 / 마감' 등으로 표기. 학교/기관 접수 확인 또는 선정 사실로 표시 금지.
- 원본 링크/제출기관/발행일/최종수정일을 표시하고, 원문 불명확 시 `확인 필요`로 처리.

## 8. 커뮤니티 운영 안전
- 로그인과 승인된 시연 소속을 이용하되 학교 공식 인증과 혼동하지 않음.
- 신고·차단, 관리자 숨김, 반복 스팸 제한, 유해 콘텐츠 조치 로그, 재노출 정책이 필요.
- 채팅 알림 피로를 줄이기 위해 중요 공지/멘션/전체 알림을 분리하고 학생이 채널 알림을 끌 수 있도록 권장.

## 9. 미결정 — 반드시 팀이 정할 항목
- 실제 학교 인증/실명 검증 방식(해커톤은 시연용 승인 계정으로 충분)
- 전체 학생/학과 익명게시판의 교수·조교 참여 정책
- 교실 질문 기본 공개 범위(해커톤 기본 교수/학생 수강생 공개로 가정 가능)
- 채팅 보존 기간, 탈퇴시 삭제/보존 세부 정책(해커톤 전 개인정보 고지 필요)
- 교직원 공지 삭제와 감사 보존의 실제 운영 승인 정책
