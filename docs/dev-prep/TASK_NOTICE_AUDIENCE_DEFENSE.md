## 재현한 결함과 수정

기존 `NoticeService.deliver()`는 `find_default_channel(department_id, grade)`가 반환한 채널을 재검사하지 않았다. 테스트 전용 저장소가 다른 학과·학년·종류의 채널을 반환하면 참조 카드가 생성되고 성공으로 집계되었다. 실제 공격·DB 오배포가 관찰되었다는 뜻은 아니다. 조회 시 `can_read_notice()`의 원문 권한 검사는 별도로 존재하므로, 원문 본문 누출이 입증되었다고 주장하지 않는다.

이제 공지 원본의 `delivery_targets()`와 반환 채널의 다음 항목을 대조한다.

1. 학과 UUID가 정확히 같아야 한다.
2. 학과 전체 공지는 `DEPARTMENT_ALL` 및 `grade=None`이어야 한다.
3. 학년 공지는 `DEPARTMENT_GRADE` 및 정확한 정수 학년이어야 한다. Python의 `True == 1` 비교가 학년 일치를 대신하지 못한다.

하나라도 다르면 카드 쓰기를 호출하지 않고 기존 `missing_targets`에 남긴다. 원본 발행과 전달 실패를 분리하는 기존 계약을 유지한다. 정상 저장소로 복구한 뒤 같은 공지 ID로 재시도할 수 있고, 카드에는 공지 원문을 복제하지 않는다. 공지 개정 후 카드 조회는 같은 원본의 최신 revision을 읽는다. 학교 전체 공지를 모든 채팅에 복제하지 않는 DFLT-004도 유지한다.

## 영속 연결 전 차단 조건

실제 저장소·worker를 연결하려면 공통 DB 소유자가 다음을 별도 설계·검토해야 한다. 이번 PR은 SQL·마이그레이션·런타임 가짜 저장소를 추가하지 않는다.

- 공지 ID 하나가 유일한 원본이며, 카드의 `(channel_id, reference_notice_id)` UNIQUE를 DB에서 보장한다. 재시도 때 원문을 새로 복제하지 않는다.
- 현재 승인된 작성 범위와 학적·역할을 공통 인증 원장에서 읽어야 한다. 교수·조교 역할 이름만으로 작성 권한을 새로 부여하지 않는다.
- 채널의 학과·학년·종류 확인부터 카드 삽입까지의 동일 UOW/잠금 또는 동등한 불변 조건을 보장해야 한다. 이 서비스 검사만으로 실제 DB 경합을 검증했다고 간주하지 않는다.
- 원본의 상태·revision CAS와 전달 작업의 재시도/중복 방지는 영속 저장소에서 보장해야 한다. 프로세스 종료 후 복구와 실패 전달 추적은 현재 단위 테스트의 증거 범위 밖이다.
- 실제 공지원장·outbox 스키마, 직원 권한 매핑, 운영 활성화에는 별도 승인·검토가 필요하다. 현재 P0 공통 로그인과 기존 핵심 CRUD에는 변경이 없다.

NAV·통합 진행표는 공통 문서 소유자가 실제 병합 결과에 맞춰 갱신한다. 작성자는 이 보안 보완 PR을 직접 병합하지 않는다.
