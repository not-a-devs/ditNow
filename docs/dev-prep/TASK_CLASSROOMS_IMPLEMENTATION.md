# TASK-G-CLASSROOMS — 강의실 1차 구현

상태: **PARTIAL / TESTED**(공급자 독립 코드·테스트 어댑터 범위). 운영 인증·MariaDB·실제 수강생/교수 권한·전역 앱 연결은 **BLOCKED / NOT_RUN**이다. FR 전체나 서비스 운영을 VERIFIED로 표시하지 않는다.

## 선행 기준과 소유 범위

관련 요구사항은 [FRD](../02_FRD.md)의 FR-COURSE-001~005/007, [통합 FRD](../v1-draft/02_FRD.md)의 FR-LMS-001~003, RBAC-COURSE/RBAC-LMS, NFR-SEC-001/002/004/005/007, NFR-PRIV-003, NFR-REL-001/003/005, NFR-DATA-003, NFR-UX-001/003/005다. FRD의 수강생 한정·담당 교수 권한·공식 출결과 온라인 학습 분리 결정을 보존한다. FR ID나 확정 결정은 변경하지 않는다.

수정 범위: `services/api/app/features/classrooms/`, `services/api/tests/test_classrooms_firstpass.py`, `apps/web/src/features/classrooms/`, 이 태스크 기록. 공통 인증·DB·마이그레이션·라우터·셸·패키지·기존 mvp 코드는 수정하거나 복사하지 않는다.

학기/분반/수강/담당 교수는 승인된 공통 기반이 권위 원장이다. 이 모듈은 생성하거나 권한을 부여하지 않는다. 현재 default 의존성은 503이다. 저장소 어댑터 없이 성공을 돌려주거나 가짜 로그인으로 보완하지 않는다.

데이터는 시연용 `DEMO`이며 외부 학교 시스템에 접속하지 않는다. 자료·질문·과제는 offering_id에 묶는다. 질문 공개 응답에 내부 작성자 ID를 넣지 않는다. 다른 학생의 교수 전용 질문과 개인 제출은 조회 결과에서 제외한다. 모든 쓰기는 현재 승인된 수강 또는 담당 교수 역할을 트랜잭션마다 재검증한다. 모듈의 정상·검증·권한·미설치·예상외 오류 응답은 `Cache-Control: private, no-store`다. UI는 401/403 후 개인 강의실 내용을 비우고 실패 이유를 상위 화면에 유지한다.

## 처리 가정과 차단 사항

다음은 자체 시연 처리 가정이며 학교 공식 규정이 아니다: 교수에게만 질문(작성자+담당 교수), 텍스트 과제 1~2000자, 마감 UTC와 같은 시각부터 거부, 최초 제출 expected_revision=0, 이후 CAS 재제출, 질문 open→answered→resolved. 교수는 답변/해결만 수행하며 초안 과제는 학생에게 보이지 않는다. 공개 질문 기본값과 답변 후 수정/철회·장기 보존은 미확정이므로 구현하지 않는다.

현재 원장 연결 전 모든 업무 운영은 차단된다. 프로토콜의 구현 어댑터는 같은 트랜잭션에서 현재 권한/분반/상태/마감과 변경을 다루고 `(assignment_id,user_id)` 유일성, 질문의 actor+offering+method/path별 멱등 키+정규 payload 해시, optimistic revision을 보장해야 한다. 재시도도 현재 권한을 확인하며 다른 actor의 결과를 재사용하면 안 된다. 테스트에서 사용한 직렬화 fake는 배포하지 않는다. 실제 MariaDB 잠금/격리/재조회·새 세션·교차 계정 검사는 NOT_RUN이다. 100건을 넘는 자료/과제/질문의 페이지네이션 및 실제 파일 보안은 후속 필수 작업이다(NFR-REL-005/SEC-007 미충족).

전역 통합 담당자는 인증 actor/store 브리지를 승인된 공통 기반에 연결하고 라우터·OpenAPI 스냅샷·신규 타입·셸 경로를 통합해야 한다. 이 PR은 해당 공유 파일을 변경하지 않는다. 운영 인증·DB 설치를 통과한 것으로 해석하지 않는다.
