# QA / 수용 테스트 / 심사 증거 명세

## 1. 필수 점검 계정과 시드
- `STUDENT_A`: 학과 A 2학년, 강의 X 수강
- `STUDENT_B`: 학과 A 2학년, 강의 X 수강
- `STUDENT_C`: 학과 B 1학년, 강의 X 미수강
- `PROF_X`: 강의 X 담당 교수
- `ASSISTANT_A`: 학과 A 조교 / 공식 공지 작성 권한
- `ADMIN`: 조직·역할 관리자
- 계정 암호·토큰은 문서에 기록하지 않음. 심사 채널에 필요한 계정만 전달.

## 3. README 첫 세 기능 평가용 시나리오 (제안)
- `#1 익명 자유게시판 게시글` → 학생 A로 글 생성→목록→새로고침→수정→삭제.
- `#2 실명 팀원 모집 게시글` → 학생 A로 모집 생성→목록→새로고침→수정→마감/삭제(승인된 신청이 있으면 삭제정책 검증).
- `#3 나의 지원 기회 관리` → 학생 A로 기회 저장/준비 체크 추가→목록→새로고침→편집→저장 취소/삭제.
- 심사자가 단일 학생 계정으로 첫 3개를 수행할 수 있게 하며 공식 공지 발행은 별도 `ASSISTANT_A` 계정으로 보여 준다.
- 이 선택은 **팀 최종 승인 전 제안**이며, README에 들어갈 첫 세 항목과 테스트는 반드시 동일해야 한다.

```

  TC-005-notice-routing/ {screenshots, steps.md, test.log}
  TC-011-live-share/ {screenshots, steps.md, test.log}

```
- 각 TC 결과: `PASS / FAIL / BLOCKED / NOT_RUN`; 코드 위치·실행 환경·날짜·스크린샷/로그 링크.
- **AI 리뷰만으로 PASS 불가**. 실제 검증/도구 실행/관찰이 필요.

## 5. 릴리스 차단 조건
- 타 계정 자료 노출, 익명/실명 연결 정보 유출, 공식 배지 무단 생성, 제출용 핵심 3 CRUD 실패, 로그인 불가, 서비스 URL 접속 불가, API 키 노출.
- 외부 장학금 지원이 실제로 완료된 것처럼 오인시키는 문구, 화면 공유 자동 시작, 수강생 아닌 계정의 라이브 시청.
