# 4분 시연 대본 — 검증 조건부

상태: 대본 DOCUMENTED, 실제리허설 NOT_RUN. 관련 [현재판정](SCORECARD.md), [실행증거](DEMO_EVIDENCE.md), [공식기준](RUBRIC.md).

## 시작 전 중단 조건

운영자가 정확한 시연SHA·로그인·기존3CRUD·이번 실행의모집/세션정리를 확인해야 라이브를 시작한다. 최신 HTTP실패와 NOT_VERIFIED가 해소되지 않았으면 이 대본을 성공시연이라고 실행하지 않는다. 새계정/시드/DDL/관리자역할/실제LLM/공개배포를 대본때문에 만들지 않는다. 승인된가상A/B만 사용하고 비밀번호·토큰·개별UUID를 화면/발표자료에 표시하지 않는다.

## 실패 시 정직한 대체

- 요청실패면더블클릭/자동재시도하지않고오류·불확실저장을그대로보인다. 운영자가기존요청키/이번marker에맞는정리·세션폐기를확인한다. 모르는기록을DB에서지우지않는다.
- 최신실행이막히면 “현재라이브는실패/진단중”이라고말한다. 과거실행SHA·시각·범위가표시된마스킹자료또는[실행기록](DEMO_EVIDENCE.md)만별도열어설명한다.
- 이작업에서녹화/사진실재를확인하지않았다. 없는영상·새성공화면을만들어보여주거나과거자료를지금라이브라고표시하지않는다.
- 대체설명은실제구동점수를회복한증거가아니다. 발표자료와서버/브라우저메모리기능은MariaDB영속성증거가아니다.

## 3분 질의응답 준비

1. **실제 학교 연동인가?** 자체플랫폼이다. 공개안내출처와가상개인원장을구별한다.
2. **AI인가?** 현기회추천/초안은규칙기반이다. LLM계약/검색패키지가있어도실제생성성공을말하지않는다.
3. **왜새로고침시로그인해제인가?** 토큰은브라우저메모리이며재로그인후MariaDB개인기록을다시조회한다.
4. **92개가완료됐나?** 아니다. 부분모듈/운영미연결/메모리시연을진행표로분리한다.
5. **데이터/권한/동시성은?** P0는공통현재신원·소유권·DB멱등/CAS를사용한다. 실제운영부하·신규관리자정책·모든모듈DB연결은미검증이다.
