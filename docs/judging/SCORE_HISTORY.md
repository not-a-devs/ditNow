# PR별 모의 심사 이력

공식 점수가 아닌 추정이다. 기준·배점은 [RUBRIC](RUBRIC.md), 현재 평가는 [SCORECARD](SCORECARD.md)를 따른다.

| 평가 | main SHA·PR | 코드 보수/기준/낙관 | 대면 보수/기준/낙관 | 이전 대비 | 새 증거 | 잔여 위험·다음 TOP3 |
|---|---|---|---|---|---|---|
| J-000, 2026-10-30 | `197436f80a9f7bb35895a019eb9b04dffc7bf847`, PR74까지 | 11/17/23 | 12/21/30 | 최초 기준. 이전 점수 발명 없음 | 실제 P0 HTTP·2폭 E2E·동일 main CI 기록 | 배포·README 대응·AI 실모델 미검증. TOP3는 배포 준비/CRUD 동선·README/기회 확인저장 |

## 병합 후 갱신 절차

1. GitHub main merge SHA, 관련 PR, 같은 SHA의 CI 결론을 확인한다.
2. 파일·테스트·실행 기록에서 이번 PR이 추가한 증거만 분리한다.
3. 실제 HTTP·MariaDB·브라우저·LLM·배포와 단위 테스트를 각각 표시한다.
4. 미검증 항목은 그대로 유지한다. 일반 문서 PR은 기본적으로 점수 변화 0이다.
5. 이전/현재 추정, 새 충족 세부 항목, 남은 위험, 가장 영향 큰 TOP3를 갱신한다.

수동 검토 절차이며 GitHub 이벤트를 자동 수신하는 상시 서비스가 구현됐다는 뜻은 아니다. 현재 세션에서 병합할 때 적용한다. 승인 대기 PR을 병합된 것처럼 기록하지 않는다.
