## J-002의 증거 구분

- 과거 `eebc1b42ef1fae7d97e53035378427943571b9f6`의 10:38~10:40 규칙 기반 기회 흐름17단계 PASS 및 앞선 핵심21단계 PASS는 실행 기록에 유지한다.
- 그 실행의 캡처10토큰 폐기와 전역 DB세션 정합성 INCOMPLETE를 구별한다. 미귀속 기존 세션을 임의 삭제하지 않았다.
- 이후 운영자가 main25fa4cf에서 수행한 두 HTTP 실행은 FAIL이다. 둘째 실행의 모집/세션 정리는 NOT_VERIFIED. root가 원인을 진단 중이며 성공으로 덮지 않는다.
- 문서 기준4305fcf의 CI6성공은 직접 확인했다. 실제 HTTP·브라우저를 이 SHA에서 실행했다는 뜻이 아니다.
- 가상 지원5·프로필·액션·채널의 단위 및 모의 브라우저 PASS는 해당 코드의 검사다. 서버 프로세스 메모리를 공유 DB 원장으로 채점하지 않는다.
- 새 4분 대본은 [DEMO_SCRIPT](DEMO_SCRIPT.md)이며 실제 리허설 NOT_RUN이다.

## CI 이력 보존

PR76 merge11bc9fe986274c5d3bea78d5b6d99688a5e52567의 CI5성공 기록은 유지한다. PR75/77 일부 중간 main 실행은 후속 병합 concurrency로 CANCELLED였다. 최종49cf5759의 실제6성공을 확인한 뒤 J-001을 기록했으며 중간 main을 모두 성공이라고 하지 않는다. J-002 역시 새로운 main/PR HEAD마다 정확한 결과를 확인한다.

문서 개수·단위 테스트 수·PR 병합만으로 점수를 올리지 않는다. 새로운 실행 증거가 없으면 변경은 상태·위험·우선순위이며 점수 상승은 0이다.
