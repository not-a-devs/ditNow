## D. 결정 변경 프로토콜
- ID, 날짜, 제안자·승인자, 이전 결정, 새 결정, 근거, 영향 파일·태스크, 되돌리기 전략.
- AI는 미결정을 발견하면 가능한 안전한 독립 작업을 먼저 진행하고, 의존 태스크만 BLOCKED로 처리.
- FRD/NFR/RBAC/테스트 간 충돌이 있으면 추측으로 수정 금지; 의사결정 요청 항목을 하나의 배치로 제시.

## E. 2026-10-30 사용자 정정과 적용 순서
- 승인 근거는 현재 작업 대화에서 사용자가 명시한 DEC-016~018이다. DB 접속·유료 계정·배포·관리자 생성 승인을 받았다는 뜻은 아니다.
- 기존 DEC-001~014와 92개 FR ID를 보존한다. DEC-002의 장기 제품 범위를 삭제하지 않고 전체 1차 구현 추적으로 확장한다. DEC-015의 DB 후보 문장만 DEC-016이 대체한다.
- 기존 사전 프로토타입은 삭제하지 않는다. 신규 앱과 제출 경계를 분리하고 제출 산출물에서 제외한다. chatbot 재사용은 사용자의 명시 지시이며 제출 전 제작시점·대회 적용 범위를 확인한다. 허용 여부 증빙을 꾸미지 않는다.
- DB 공급자/비용·인증·개인정보·파괴적 migration은 사람 승인 게이트를 유지한다. 독립 모듈은 먼저 구현·테스트하고 공통 계약 병합/실DB 통합 전 VERIFIED로 표시하지 않는다.
- 되돌리기: 신규 앱·통합 어댑터를 별도 브랜치/PR로 관리하며 기존 chatbot 실행 경로를 회귀 검사한 후 단계적으로 대체한다. 사전 MVP로 최종 앱을 되돌리지 않는다.
