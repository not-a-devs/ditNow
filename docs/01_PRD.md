# PRD — DIT Campus 통합 캠퍼스 플랫폼

## 1. 한 문장 정의 [확정 방향]
기존 대학 웹·앱의 주요 기능을 자체적으로 재구현하고, **학사·수업·공지·소통·기회 발견·협업이 한 데이터 체계로 연결되는** 동의과학대학교 차세대 통합 웹 플랫폼을 제안한다.

## 2. 제품 비전 / 차별화
- 기존 웹/API를 링크 모음으로 묶지 않는다. 새 계정·DB·권한·업무 흐름을 가진 독립 서비스다.
- 기본 기능(학사, 수업, LMS, 출결, 과제, 공지, 행정, 도서관, 학교생활, 관리)은 장기 제품 기준선으로 모두 설계한다.
- 신규 차별점: 학과 단톡의 실제 대체를 지향하는 채널형 소통, 공식 공지 자동 배포, 익명 자유 커뮤니티+실명 협업, 공모전→팀원 모집, 외부 장학금 서류·마감 안내, 교수 화면 실시간 공유, 개인화 액션 센터/AI.
- **전체 설계 범위 = 해커톤 구현 약속이 아님.** 실제 구현·시연은 범위를 분리해 진술한다.

## 4. 주요 페르소나 / JTBD
- **학생**: 소속 학과 채팅/학사 공지/수업 자료/지원 기회를 별도 사이트 이동 없이 확인하고, 필요하면 스터디·프로젝트 팀원을 구하고 싶다.
- **교수**: 수강생에게 강의 공지·자료·과제를 전달하고, 대면 실습 중 학생에게 화면을 보여주며 질문에 답하고 싶다.
- **조교/학과 담당자**: 동일 공지를 학년 총대에게 따로 전달하지 않고 승인된 대상에 정확히 게시하고 싶다.
- **학년 총대**: 학년 채널과 학생 의견을 관리하되 공지 복사 중계의 부담은 줄이고 싶다.
- **관리자**: 학과·학년·과목·수강생·역할·공식 채널·신고를 감사 가능한 방식으로 관리하고 싶다.

## 5. 정보 아키텍처 (제품 전체)
1. 홈/통합 액션 센터: 오늘 수업, 공지, 마감, 팀 지원, AI 정리
2. 내 강의실: 수강 과목/강의 공지/자료/과제/출결/실시간 수업/수업 채팅/질문
3. 우리 학과: 학과 전체/학년별 채팅, 학생 자유 채널, 공식 공지, 학과 게시판
4. 커뮤니티: 전체 익명 자유게시판, 질문, 실명 팀 모집·스터디·동아리, 채팅
5. 기회 센터: 장학금·근로·취업·공모전·행사, 원문·지정 양식, 준비 체크/마감
6. 학사/캠퍼스: 시간표·수강신청·성적·학사 행정·도서관·시설·교내 지도
7. 교직원/관리자: 공지·수업·접수·조직·권한·신고·감사 관리

## 6. 경험 원칙
- **하나의 원본**: 공지는 `notice` 하나만 보존, 학과·학년·수업 채널에 전달되는 메시지는 링크 카드다.
- **소속 기반 접근**: 학생의 실제 등록/승인된 학과·학년·수강 정보를 기준으로 목록과 권한을 계산한다.
- **익명과 실명은 분리**: 익명 글은 실명 프로필/팀원 활동과 역추적 UI를 연결하지 않는다.
- **공지와 잡담 분리**: 공식 소식함은 독립적으로 유지하면서 관련 채팅에는 자동 카드 게시.
- **정보→행동**: 공고를 저장하고 준비서류·마감·신청 진행을 관리. 외부 접수 완료는 학생 자체 기록.
- **실제 대면수업 지원**: 화면 공유는 수업 자료 열람과 병행; 일반 영상회의 전체 복제 아님.
- **정확성**: AI는 원문에 없는 자격/마감/출결 정보를 생성하지 않는다.

## 7. 대표 사용자 흐름 (E2E)
**UF-01 공식 학과 공지 자동 배포**: 조교 로그인 → 학과·학년 대상/기간 작성 → 게시 → 원본 공지 저장 → 대상 학과 채널의 공식 카드 자동 게시 및 알림 → 학생 채팅에서 열람 → 상세/첨부 다운로드 → 수정 시 동일 원본 최신판 제공.

**UF-02 외부 장학금 발견·지원 준비**: 학교 담당자 공고+양식/제출처 등록 → 관련 학생 기회 피드 노출 → 학생 원문/자격 확인 → 양식 다운로드 → 개인 체크리스트·마감 저장 → 외부 기관에 직접 제출 → 학생이 수동으로 제출 여부 표시.

**UF-03 학과 소통**: 학생 로그인 → 자신의 학과 전체/학년 채널 자동 노출 → 채팅/파일/공식 카드 확인 → 자유 채널 개설/참여; 학과 공지의 원본과 채팅 대화의 신뢰도를 구별.

**UF-04 익명→실명 협업(경계 유지)**: 학생 익명 자유게시판 이용 → 별도 실명 프로젝트 모집 영역 이동 → 공개 실명 프로필로 모집/지원 → 팀 구성·팀 채팅; 익명 글 작성자와 실명 프로필은 자동 연결하지 않음.

**UF-05 수업 전·중·후**: 관리자가 개설한 강의/수강 정보 → 학생 시간표/내 강의실 표시 → 교수 자료·공지·과제 게시 → 교수 PC 화면 공유 시작 → 수강생 화면 확대 및 원본 자료 열람 → 수업 채팅/교수 질문 기능 → 종료 후 과제 제출·피드백.

## 8. 목표 / 성공 판단
- 제품 목표: 정보 발견·전달의 단계 축소, 학과 단톡 대체 유인, 학과 간 협업 기회 확대, 수업 자료 가독성 개선.
- 해커톤 성공 기준: 공개 서비스·로그인, README 첫 3기능의 서버 DB CRUD, 공지→대상 채널 교차 데이터 흐름, 권한/입력/오류 처리, 실제 데이터 기반 AI, 모바일/PC 동작을 증거로 보인다.
- 측정 후보(배포 후): 공지 확인율, 공지→지원 준비 전환, 자유채널 생성·참여, 모집글 지원율, 강의 자료 조회, 실시간 수업 참여 안정성. 실제 데이터가 없으므로 수치/효과를 사실처럼 쓰지 않음.

## 9. 비목표와 사실 경계
- 기존 학교 SSO, 학생정보·성적·공식 출결 데이터와 **실제 연동하지 않음**.
- 실명 프로필 표시 ≠ 학교가 재학생 신분과 실명 일치성을 검증함.
- 장학재단 제출 서류를 자동 접수하거나 외부 기관의 결과를 자동 추적한다고 주장하지 않음.
- 외부 서비스/자료의 무단 수집·가짜 공식 명칭·가짜 합격/지원 결과 생성 금지.
- 대학 실운영 배포는 해커톤 시연과 별도의 권한/법적/운영 검증 필요.
