# DIT NOW 테스트·QA 기준 v1.0 초안

기존 [QA](../08_TEST_QA.md)의 TC-001~018을 유지한다. [기능 추적표](09_FEATURE_TRACEABILITY.csv)의 92개 TC-V1-*는 각 FR에 정확히 1개씩 대응하는 최소 수용 시나리오 ID다. 실제 테스트 실행 결과는 아직 없다. PASS/FAIL/BLOCKED/NOT_RUN 중 실행 증거가 있는 상태만 기록한다.

## 공통 테스트 행 계약
TC-V1-*마다 (1) 권한 있는 역할과 가상 시드, (2) 입력/트리거, (3) 기대 출력과 DB 상태, (4) 새로고침·재로그인, (5) 타 계정·타 범위 거부, (6) 중복·마감·동시성·네트워크 오류 중 해당 예외, (7) 출처/가상 표시를 점검한다. 추적표 test_scenario_acceptance는 기능별 추가 검증이다. 문서에 적힌 일반 문구만으로 PASS할 수 없다. P2 정책 차단 기능은 시연 가능 범위와 실제 운영 차단을 분리한다.

## 자동 검증 게이트
문서 단계: 92 고유 ID, 기존 48/신규 44, 모든 행의 AC·DB·RBAC·API·NFR·TC·출처·우선순위, 로컬 링크 존재, 상태값과 문서 간 충돌을 스크립트로 확인한다. 이는 명세 검증이며 애플리케이션 테스트가 아니다.
구현 단계: 타입 검사/린트/빌드/단위·통합·E2E/보안/두 계정/DB 영속/390·1280 화면/성능/배포 검증을 해당 태스크에서 수행한다. 실제 명령은 저장소 패키지와 CI가 존재하는 시점에 확정한다. 현재 문서만으로 CI/브라우저/DB가 PASS했다고 표시하지 않는다.

## 릴리스 차단
타 계정 개인자료 노출, 익명 작성자 노출, 학생의 공식 권한 획득, 비공개 상담/고충 유출, 실제 학교 연동·결제·증명 허위 표시, P0 핵심 CRUD 또는 공지 연결 실패, 근거 없는 AI 학사 판정은 RELEASE_BLOCKER. 미구현 P1/P2는 화면과 보고에서 명시한다. 실제 통과/실패 기록은 날짜·환경·커밋·증거 링크를 갖춘다.
