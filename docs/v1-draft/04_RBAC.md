# DIT NOW 역할·권한 정책 v1.0 초안

기존 [RBAC](../04_POLICY_RBAC.md)의 확정 익명/실명 분리, 학생 자유채널과 승인된 공식채널, 학과·학년·분반 대상 공지 원칙을 유지한다. 신규 업무 역할은 [조사](../research/05_FUNCTIONAL_REQUIREMENTS_GAPS.md)에서 도출한 설계 가정이다. 학교의 실제 교직원 권한을 확인했다는 뜻이 아니다.

## 권한 계산
권한 = 인증된 사용자 + 현재 승인된 role_assignments(role, scope_type, scope_id) + 자원 소유/상태 + 유효 소속/수강 + 민감도. 클라이언트 입력 role·학과·학년은 신뢰하지 않는다. FastAPI가 세션 검증과 매 요청 자원 권한을 책임지고, PostgreSQL 채택 시 최소 GRANT/RLS를 별도 방어선으로 적용한다. DB 후보가 미확정이어도 서버 권한 검증은 생략할 수 없다. 역할 승격·학적 변경은 감사 이벤트가 필요하다.

## 중요한 상태 경계
지원자→학생, 재학생→휴학/졸업, 학과 전과, 수강 취소가 승인되면 토큰의 오래된 claim만 믿지 않고 DB 권한을 재평가한다. 이전 채널·강의 파일·라이브 구독을 즉시 끊는다. 민감 고충은 일반 관리자에게도 기본 거부하고 별도 배정 및 접근 로그를 요구한다. 익명 작성자 매핑은 신고 처리에 필요한 최소 범위에서만 보며 공개 응답에는 절대 넣지 않는다.

## 시연과 운영 승인
시연 역할·소속은 관리자 시드가 승인한 가상 계정이다. 실제 학교 SSO나 재학생 신분을 주장하지 않는다. 실제 결제/환불/증명/성적 확정/상담 본문은 이 권한표만으로 활성화할 수 없다. [미확정 정책](11_OPEN_POLICIES_ASSUMPTIONS.md) 승인이 선행된다.
