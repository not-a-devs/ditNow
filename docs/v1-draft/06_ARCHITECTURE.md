# DIT NOW 서비스 아키텍처 v1.0 초안

[DEC-015](../11_DECISION_LOG.md)에 따라 React/TypeScript/Vite/Tailwind CSS 프런트엔드와 FastAPI 백엔드는 확정이다. DEC-016의 MariaDB 제품은 확정이며 DB 운영·인증·스토리지·실시간·호스팅 공급자와 비용은 OPEN-002 미결정이다. [기존 아키텍처](../06_ARCHITECTURE.md)를 이 결정에 맞춰 읽는다. mvp는 사전 프로토타입으로 최종 서비스/시연/제출에서 제외한다. apps/web을 소스 복사 없이 새로 작성한다(DEC-018). `services/api/`의 공개 health·오류·설정·로그·테스트 기반과 아래 미구현 업무 API·공유 DB를 구별한다.

## 논리 계층
React/Vite 클라이언트(공개/지원자/학생/교직원 화면) → FastAPI 인증·권한·Pydantic 검증 → 업무 서비스(공지·채팅·협업·기회·강의/LMS·학사·입학·도서·생활·지원) → 선택된 DB 원장/비공개 파일 저장. MariaDB 전용 최소 GRANT·FK·unique·트랜잭션과 서버 스코프 질의를 사용한다. 네이티브 PostgreSQL RLS는 전제하지 않는다. outbox 소비자가 공지 카드·알림·검색 갱신을 처리한다. AI 서비스는 권한 필터된 최소 원본만 읽는다. 화면 공유 공급자는 별도 짧은 토큰으로만 연결한다. 실제 학교 운영 시스템은 이 시연 경계 밖이다.

## 통합 경계와 권위
공개 학교 자료는 URL·확인일을 가진 출처 스냅샷이며 운영 원장이 아니다. 개인 계정·수강·성적·출결·신청 상태는 자체 가상 원장이 유일한 시연 권위다. 향후 학교 시스템 연계는 OPEN-R01/R02, 계약·동의·대사·지연/충돌 처리 결정 이후 별도 ADR로 설계한다. 외부 학교 API의 비공개 호출을 전제하지 않는다.

## 공통 서비스 불변식
1. 공식 공지 원본은 notices 한 건; 학과/학년/수업 채팅과 알림은 ID 참조와 revision만 보유한다.
2. 소속/분반 변경은 접근 재평가 이벤트를 발생시키며 API·실시간·파일 서명 URL 모두 새 권한을 적용한다.
3. 익명 공개 글/댓글은 author_id 없는 projection으로 제공하며 실명 팀 공간은 별도 공개 프로필이다.
4. 공고→개인 준비→실명 팀 모집은 opportunity_id로 연결한다. 외부 제출 상태는 개인 자기 기록이다.
5. 강의실 자료·과제·질문·채팅·화면 공유는 offering_id와 enrollments 권한을 공유한다.
6. 홈·검색·알림은 도메인 원장을 복제한 최종 권위가 아니며 원본 상태/권한을 다시 확인한다.
7. 민감 상담·고충, 입학/성적, 결제·증명 원장은 별도 최소 권한과 감사 경계를 갖는다.

## 신뢰/실패 모델
클라이언트 상태와 URL은 신뢰하지 않는다. FastAPI는 매 요청 인증·범위·입력·상태를 검증하고 선택된 DB의 FK/unique/트랜잭션으로 경합을 막는다. MariaDB 계정 권한과 제약은 FastAPI의 현재 신원·소유권 검증을 대체하지 않는다. 이벤트 소비 실패는 outbox에 남고 재시도하되 카드/알림 고유키로 중복을 막는다. 실시간 이벤트를 놓치면 재조회로 복구한다. AI/미디어/외부 링크 장애는 핵심 원장 읽기·쓰기의 성공과 별도로 표시한다. 로그/분석에는 민감 본문·토큰을 기록하지 않는다.

## 단계별 구현 경계
P0는 기존 [릴리스 범위](../09_RELEASE_SCOPE.md)의 핵심 3 CRUD·공지 배포·학과 채팅·AI 실패 안전성을 검증한다. P1의 화면 공유는 1교수+2학생, 권한 거부·종료·재접속 PoC가 통과해야 시연 경로에 올린다. P2는 요구사항·권한·데이터·테스트 설계를 유지하되 학교 정책 미확인을 구현 완료로 보지 않는다. 세부 의존성은 [AI 태스크 기준](10_AI_TASK_RULES.md)을 따른다.

## 전체 1차 구현과 RAG
DEC-017의 chatbot은 공통 사용자·학적 원장과 세션을 쓰는 한 기능이다. standalone demoauth와 분리된 개인 원장을 통합앱에 mount하지 않는다. 공개 검색 adapter부터 연결하고 개인조회는 공통 인증 승인 후 연다. DEC-018에 따라 92개 전체를 1차 구현 대상으로 두며 P0 이후 P1/P2 독립 작업을 계속한다. [병렬 보드](../dev-prep/05_PARALLEL_IMPLEMENTATION_BOARD.md)가 파일 소유자와 의존성을 관리한다.
