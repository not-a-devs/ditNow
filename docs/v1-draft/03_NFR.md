# DIT NOW 통합 NFR v1.0 초안

[기존 NFR](../03_NFR.md)의 NFR-SEC-001~007, PRIV-001~003, REL-001~005, DATA-001~003, PERF-001~004, UX-001~005, AI-001~004, STREAM-001~003, OPS-001~004를 유지한다. [조사 보완](../research/06_NON_FUNCTIONAL_REQUIREMENTS_GAPS.md)의 신규 NFR-ID-001~002, PRIV-004~005, SEC-008~009, REL-006~008, OPS-005~006, UX-006~007, AI-005를 추가 설계 후보로 둔다. 기존 해커톤 성능 목표 90점을 장기 운영 SLA라고 주장하지 않는다.

## 인증·정보 경계
- NFR-SEC-001~009: 서버 인증·범위 권한·입력/출력 검증·비밀키 보호·요청 제한·파일 통제·승인/감사. 로그인 UI 숨김으로 권한을 구현한 것으로 보지 않는다.
- NFR-ID-001~002: 지원자/학생/졸업생/교직원 신원 전환은 승인된 이벤트로만 가능. 학적/분반 변경 후 API, 실시간 구독, 서명 URL의 이전 권한이 즉시 무효여야 한다.
- NFR-PRIV-001~005: 익명 공개 응답에서 식별자 제거, 민감 정보 최소 수집, 상담·고충·성적·이력서·도서 대출의 자원별 접근 정책과 보존 정책. 공개 자료에는 출처·확인일·가상 여부를 붙인다.
- NFR-SEC-009: 민감 고충은 일반 검색, AI 프롬프트, 알림 본문, 일반 관리자 목록, 분석 이벤트에 제목/내용이 새지 않는다.

## 정합성·장애
- NFR-REL-001~008: DB 영속성, outbox 재시도 멱등성, 정원·재고·슬롯 경합, 요청/확정 상태 분리, 타임아웃과 부분 실패 복구. 전송 성공과 실제 사용자 표시 성공은 별도로 기록한다.
- NFR-DATA-001~003: 공식 공지 단일 원본과 참조 카드 분리; 외부 제출 자기 보고 표시; FK/unique/서버 시간 제약.
- 실패 화면에는 요청 ID, 재시도 가능 여부와 사용자가 할 다음 행동을 보여준다. 내부 예외·비밀값은 표시하지 않는다.

## 성능·접근성
- NFR-PERF-001~004 및 UX-001~007을 유지한다. 390px/1280px 화면, 로딩/빈/오류/권한/만료, 키보드·스크린리더, 색 이외 상태 표시를 모든 핵심 경로에서 검사한다.
- P0 해커톤의 모바일 Lighthouse 90+는 기존 목표다. 실제 운영 동시 접속, 가용성, RPO/RTO는 OPEN-R14 결정 전 TBD이며 측정하지 않았다.

## AI·실시간·운영
- NFR-AI-001~005: 로그인·최소 데이터·정형 출력·타임아웃·비용 제한·프롬프트 주입 방어. AI는 성적/합격/출결/장학 자격/상담 판단을 확정하지 않는다.
- NFR-STREAM-001~003: 교수 송출 권한, 수강생 시청, 명시적 화면 선택, 오디오/녹화 OFF, 종료·재접속·미지원 대응. 기능이 구현되지 않으면 NOT_APPLICABLE_YET로 기록한다.
- NFR-OPS-001~006: 재현 가능한 환경, 테스트 증거, 비밀값·실사용자 데이터 배제, 공개 데이터 갱신 책임과 백업/복구 수치 결정. 운영 수준 검증 전 실운영 준비 완료 표시 금지.

## 기능별 적용과 합격
[기능 추적표](09_FEATURE_TRACEABILITY.csv)의 nfr 컬럼은 각 기능의 최소 연결이다. 공통 NFR-REL-001/UX-001을 모든 행에 적용한다. 권한·익명성·민감 데이터 위반은 [QA](08_TEST_QA.md)의 RELEASE_BLOCKER. 수치/보존기간/가용성 미정은 TBD로 두고 PASS라고 적지 않는다.
