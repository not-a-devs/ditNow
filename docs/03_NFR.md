# NFR — 비기능 요구사항 및 검증 기준

> `shall`에 해당하는 필수 요구를 **측정 가능한 조건과 증거**로 작성한다. 목표 값은 공식 규정과 팀 설계 가정으로 구별한다.

## 보안·권한·개인정보
| ID | 요구사항 | 검증 방법 / 합격 조건 | 성격 |
|---|---|---|---|
| NFR-SEC-001 | 인증된 사용자는 FastAPI가 검증한 유효 세션/토큰으로만 보호 API 접근. 공급자·방식은 OPEN-002 미결정 | 비로그인·만료·폐기 401, 로그아웃 이후 거부. JWT 채택 시 서명·만료·발급자·대상 검증; 불투명 세션 채택 시 서버 조회·만료·폐기 검증 | 필수 |
| NFR-SEC-002 | 공통 FastAPI 세션의 개인/학과/수강 권한을 서버 인가·MariaDB 최소 권한·스코프 질의로 강제. chatbot도 같은 사용자/학적 권위를 사용 | ID 변경 공격, 다른 학과/학생 계정으로 R/W/U/D 모두 차단. 누락된 소유/부모 범위와 별도 chatbot 로그인 우회 거부 | 필수 |

## 합격 판정 규칙
- 기능 구현 시 연관 NFR을 동시에 통과해야 `done`이 된다.
- 타계정 데이터 노출, 비밀키 노출, 익명↔실명 신원 누출, 무단 공식 권한 부여는 **즉시 릴리스 차단**.
- 성능 90점은 목표이지 현재 달성 사실이 아니다. 측정값과 평가 기준을 구분한다.
- 스트리밍 미구현 상태에서는 NFR-STREAM을 `not_applicable_yet`, 실제 구현 후에는 반드시 검증.
